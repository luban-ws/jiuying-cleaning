# RFC 004：完全磁盘访问与受限路径引导

**状态**：已完成  
**创建日期**：2026-04-12  
**作者**：CleanSpace  
**依赖**：[RFC 001](./001-ccleaner-style-cleaning-spec.md) 风险与权限

---

## 实现备注（与代码对齐）

- 触发逻辑：`FullDiskAccessGuidance`（须有 `EPERM`/`EACCES`/Cocoa 无权限错误；**禁止**仅因体积为 0）。
- 扫描侧收集拒绝路径：`scanRuleWithAccessReport`、`scanTopLevelFoldersWithAccessReport`。
- 共用 UI：`FullDiskAccessBanner`（规则工作区 + 磁盘页）。
- 系统设置跳转：`FullDiskAccessGuidance.openFullDiskAccessSettings()`（Ventura+ URL 优先，旧 pane 回退）。
- 手工验收：用未授予「完全磁盘访问」的账号扫描含 `~/Library/Mail` 等规则；CI 单测覆盖触发条件（见 `FullDiskAccessGuidanceTests`）。

---

## 摘要

在 TCC 限制下，部分 `~/Library` 或外置卷路径无法被应用读取，导致扫描为 0 或静默失败。本 RFC 规定：在检测到**可能因权限导致**的失败或空结果时，向用户提供**可理解的说明**与跳转「系统设置 → 隐私与安全性 → 完全磁盘访问」的引导，并说明为何需要该权限。

---

## 背景与问题

- 用户误以为「没有垃圾可清」；实际是沙箱拒绝访问。
- RFC 001 已提醒权限风险，但缺少产品内一致的体验规范。

---

## 范围

**在本 RFC 内**

- 定义触发引导的条件，**优先强信号**，避免「磁盘真干净」时的误报：
  - **主触发**（满足任一即可考虑展示引导）：`FileManager`/POSIX 打开或枚举返回 **明确权限拒绝**（如 `EPERM`、`EACCES`、或 Apple API 文档中与 TCC/沙箱相关的错误域）；或应用内维护的 **「已知在未授权时通常不可枚举」的路径前缀** 与当前规则匹配且本次操作返回上述错误。
  - **辅触发**（不得单独作为唯一条件）：在**已发生主触发**的前提下，同一规则短期内重复得到空结果，可用于强化文案或折叠频次。
  - **禁止**：仅因「连续多次扫描体积为 0」且无 errno/API 错误证据即弹窗引导（易误报）。
- 文案走 `L10n`，中英同步；不在 UI 写死 CJK。
- **诚实说明**：须包含「未授予完全磁盘访问时，部分项可能显示为 0 或不可用，**不代表**没有可清理数据」之类表述（具体措辞以 `L10n` 键为准）。
- 可选：`x-apple.systempreferences:` 打开对应设置页（若苹果允许且版本可用）。

**不在本 RFC 内**

- 申请其他 TCC（如桌面、文稿文件夹）除非与清理路径直接相关，另开 RFC。

---

## 提案要点

1. 规则页与磁盘页共用同一套「权限不足」提示组件，避免重复实现。
2. 不强制用户授权；提供「稍后」与「不再提示本条规则」类选项（若实现成本低）。

---

## 验收标准

- 在关闭完全磁盘访问的测试账号上，对已知受限路径在 **errno/API 可复现的拒绝** 场景下能出现引导，且不崩溃。
- **回归**：在无拒绝错误、目录确为空或无权访问但**未命中**主触发条件的场景，不得仅因「体积为 0」反复弹窗（可通过 UI 测试或逻辑单测断言触发条件）。
- 文档或 AGENTS 中可链接本 RFC，说明文案与本地化要求；测试说明中注明如何配置「关闭完全磁盘访问」的账号或 CI 替身（若 CI 不可行则标为手工验收项）。
