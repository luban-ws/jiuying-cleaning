# RFC 008：Docker Desktop 路径级重置向导

**状态**：草案  
**创建日期**：2026-04-12  
**作者**：CleanSpace  
**依赖**：[RFC 001](./001-ccleaner-style-cleaning-spec.md) § 3.2 路径级（Docker Desktop 残留）

---

## 摘要

CLI `prune` 不足以回收虚拟机盘内全部空间时，用户可能选择**删除 Docker Desktop 数据目录**以重置安装。该操作等同于卸载数据，风险极高。本 RFC 规定：独立**向导式流程**（多步确认、列出将删路径、建议先退出 Docker），与日常规则清理、Docker 预设命令流**隔离**，避免误触。

---

## 背景与问题

- RFC 001 已列出 `group.com.docker`、`Containers/com.docker.docker` 等路径；若做成普通勾选规则，易与「一键 prune」混淆。
- 需在 Docker 未运行时操作的建议须在 UI 中可执行检查或明确警告。

---

## 范围

**在本 RFC 内**

- 入口：仅 Docker 工作区内的显式入口（例如「重置 Docker Desktop 数据…」），不可合并进默认「运行清理」。
- 步骤：说明后果 → 展示路径列表（来自 001 表格）→ 确认 checkbox → 执行删除或调用官方推荐流程。
- 与 [RFC 007](./007-post-clean-audit-log.md) 联动：此类操作必须记审计。

**不在本 RFC 内**

- 替代 Docker Desktop 安装器或官方 uninstall 工具。
- 非 Docker 的路径级批量删除。

---

## 内置规则隔离（定案）

- 内置 schema 增加可选布尔字段 **`hiddenFromRulesList`**（默认 `false`）。Docker Desktop §3.2 **路径级**条目以固定 `id` 存在于 `cleaning-rules.json`（或与内置 bundle 等价来源），且 **`hiddenFromRulesList: true`**，使其**不出现在**常规「可勾选规则列表」中。
- **向导**通过固定 `id` 列表或专用工作区常量引用上述路径；**禁止**与普通「运行清理」共用同一勾选模型。
- 若未来新增同类高危路径级向导，复用同一字段，另开 RFC 描述产品入口即可。

## 提案要点

1. 实现上可复用 `dir` 规则解析逻辑，但 UI 与确认流与常规规则**完全隔离**（见上节）。
2. 若检测到 Docker 进程运行，默认禁止继续或仅允许「我已手动退出」后的强制继续。

## 文案与 L10n（定案方向）

- **短、可扫读**：首屏不超过数条要点（后果 / 将删路径类别 / 不可逆）；避免法律式长文导致用户盲勾「同意」。
- 必须包含 **「将丢失所有镜像与容器数据」** 或等价表述（`L10n` 键）；中英同步。

---

## 验收标准

- 用户未经过向导不能一键删除 001 §3.2 所列目录。
- 文档字符串与 L10n 明确「将丢失所有镜像与容器数据」类表述。

---

## 与 RFC 001 的关系

把 001 中「仅在用户明确确认时提供」的路径级清理产品化，且与 CLI 预设区分。
